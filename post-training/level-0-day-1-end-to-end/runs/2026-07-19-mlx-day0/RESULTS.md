# Day 0 verified end-to-end — MLX on Apple Silicon (2026-07-19)

Raw log: [`training-log.txt`](training-log.txt) — the unedited output of the four-step loop
(`gen_data` → baseline eval → `mlx_lm.lora` train → after eval).

## Setup

- **Model:** `Qwen/Qwen3-0.6B` (596M params, bf16)
- **Task:** hardened messy-record → strict JSON (dates like `"11/2/21"` → `2021-08-02`-style ISO, salaries `"$64K"` → `64000`, departments `"People Ops"` → `"HR"` — transformation, not copying)
- **Data:** 400 train / 50 valid / 60 test, generated by `gen_data.py`
- **Training:** LoRA via `mlx_lm.lora` — 400 iters, batch 4, lr 1e-4, `--mask-prompt` (loss on completion only), 8 layers adapted
- **Hardware:** Apple Silicon Mac, unified memory; eval on 30 held-out records

## Observation

| metric | base model | after SFT |
|---|---|---|
| `parse_rate` | 0.867 | **1.000** |
| `field_accuracy` | 0.673 | **1.000** |
| `exact_match_rate` | **0.133** | **1.000** |

Training: **0.242% of parameters trained** (1.442M / 596M), ~10.5 iters/sec ≈ **2,400 tokens/sec**, **peak memory 3.04 GB**, val loss 0.983 → 0.001. Wall clock ≈ 40 s.

## Insight

- The base 0.6B model *copies* fine but cannot *normalize* — it gets a complete record right only 13% of the time. One short LoRA SFT run takes it to 100% on the held-out set. This is the core claim of post-training, demonstrated: **a targeted skill installed for ~40 seconds of laptop compute.**
- A first version of this task put every field verbatim in the input; the baseline scored 0.93 and train loss hit 0.000 by iter 20 — nothing to learn. **If the base model can already do your task, fine-tuning teaches you nothing.** Hardening the task to require transformation is what made the lesson visible.
- Caveat carried forward: only the *target* skill was measured. Whether general capability regressed (catastrophic forgetting) is deliberately deferred to Level 2/5.
